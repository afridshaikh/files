# Computational Water Quality Management

A computational framework for studying water quality behaviour in drinking water
distribution networks. The project builds a virtual distribution network, simulates
hydraulic and water-quality conditions, and creates measurement-like observations
that can be used for modelling, validation and later optimisation experiments.

The current implementation uses a transparent simulation layer so that the complete
experiment can be reproduced without access to a live utility network. The generated
observations are explicitly synthetic; they are not presented as field measurements.

## What the project does

The workflow is:

```text
Network configuration
        |
        v
Virtual distribution network
        |
        v
Hydraulic and water-quality simulation
        |
        v
Reference (ground-truth) data
        |
        v
Measurement model
(noise, missing values, bounded outliers)
        |
        v
Observed dataset
        |
        v
Validation and analysis
```

The parameter ranges are based on the ranges used in the accompanying research
material:

| Parameter | Range |
|---|---:|
| Flow | 0–1,500 m³/h |
| Pressure | 0–15 bar |
| Free chlorine residual | 0–2.5 mg/L |
| pH | 6.5–8.5 |
| Turbidity | 0–5 NTU |
| Temperature | 0–40 °C |

The simulation uses 15-minute observations. The data generator also includes
normal operation and controlled changes in demand, pumping conditions and chlorine
decay so that later modelling can distinguish different operating conditions.

## Requirements

Python 3.9 or newer.

Install dependencies:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

On Windows:

```powershell
.venv\Scripts\activate
```

## Run the experiment

From the project root:

```bash
python -m src.main
```

The program will:

1. create the network topology;
2. generate reference hydraulic and water-quality values;
3. create measurement-like observations;
4. introduce controlled missing values and measurement variation;
5. check all values against the configured ranges;
6. write the resulting datasets and validation report.

## Important interpretation rule

The reference values are the values generated by the computational model. The
measurement-like values are deliberately perturbed observations.

Therefore, a difference between the two is not a modelling failure by itself.
It represents the measurement process that a later prediction model will need
to handle.

When reporting results, always distinguish:

- simulated/reference value;
- observed/synthetic measurement;
- missing observation;
- controlled outlier;
- model prediction.

## Reproducibility

The random seed is stored in `configs/config.yaml`. Keeping the same seed and
configuration reproduces the same experiment.

## Next modelling step

The next extension is to replace the transparent hydraulic/water-quality
simulation with an EPANET-backed model while keeping the network, measurement
and validation interfaces stable. This allows EPANET to provide the reference
state and preserves the same downstream dataset structure for predictive
modelling.
